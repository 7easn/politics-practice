# 仅更新主观题

此迁移供既有 Supabase 项目的管理员在官方 SQL 编辑器执行。先确认已安装本仓库的 `supabase.sql`、`private-content.sql` 和 `private-content-chunks.sql`。`subjective-only.sql` 检查已有函数归属，不创建用户、凭据或允许名单，也不导入题库内容。

安装后，本人登录现有学习室，在「题库与资料管理」选择私有交付的 `subjective-update.json`，再点「仅更新主观题」。选择文件仅在本机校验；更新会重新读取本人当前云端分片题库并核验 SHA，不使用交付方的历史基线。只替换主观题及其覆盖表，保留选择题、知识点、口诀、已有来源和学科前缀、政治及其他未允许字段。学习事件、错题、收藏和本机草稿不由此次更新写入。

新提交函数以账户、文档锁和预期基线 SHA 比较后在一个数据库事务中激活。两个同时更新只有匹配当前基线者可以成功；新旧提交函数均拒绝重新激活已完成但过期的上传。相同活动版本的重试可以成功。缺少完整基线、哈希错误、字段被改动或合并超出既有 32 MiB 上限会拒绝，不清空、删题或调高限制。旧式 JSON 存储不能替代当前分片基线。

浏览器先暂存经过校验的新缓存，再提交服务器；暂存失败在激活前停止。服务器与浏览器缓存无法共同构成一个事务，因此提交回复丢失时核对服务器活动 SHA，核对失败会显示结果未确认。服务器确认后若缓存激活失败会明确报告。当前学习界面与草稿一直保留，保存草稿后在版本提示手动切换。

本机合成账户测试通过：SQL 12项、实际两个数据库连接并发4项、桌面及手机尺寸模拟浏览器24项、上传期间退出和切号4项。历史完整基线合并895主观题为28,768,703字节，本机事务耗时约245毫秒且回滚；这些结果不证明远端性能、实际用户基线或真实手机验收。较大的本地3024题候选合并超出32 MiB，必须拒绝。实际基线也超限时，需要另行审查独立主观文档和原子版本清单方案。

网页发布不安装数据库迁移，也不切换用户题库。若新RPC尚未安装，界面会拒绝更新，不退回旧提交接口。
